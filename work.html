Governed autonomous agents

Agents that investigate, decide and act through controlled tools. Autonomy is set per workflow, from advisory to act-with-approval. Every step is logged, and consequential actions require human approval.

  1. Finance

    Autonomous financial investigation platform

    Explains why profitability moved, with an evidence trail an auditor can follow.

    Reference platform: CI, docs, synthetic ERPAutonomy: advise

    Read the full note
    The challenge
    Finance questions draw on ERPs, external filings and internal documents. An answer without provenance cannot be audited or signed off.
    The solution
    An investigation platform in which code, not the prompt, controls the process: planner → investigation loop → adversarial critic → remediation loop → deterministic verifier.
    Controls and evidence
    • Every fact is stored with its source. Every claim is classified (fact, calculation, assumption, scenario or inference) and lists the evidence for and against it.
    • Database access is read-only and guarded. State, memory, recovery and permissions are explicit policy.
    • A configuration-driven evaluation suite scores the agent before any demonstration.
    Data sources
    Guarded database queries, public regulatory filings, public macroeconomic series, internal documents, anomaly detection and a scenario engine.
    Status
    Full platform with continuous integration, documentation and a demonstration script. It runs on a labelled synthetic ERP, so it can be evaluated without client data.
    Autonomy level
    Advise. The platform reads, analyses and reports, and a person acts on the findings.
    Relevant to
    Corporate finance, internal audit and risk functions.
    Technology
    Python 3.11, FastAPI, SQLAlchemy (Postgres/SQLite), Pydantic, OpenAI Responses API, Next.js, Tailwind, Docker Compose, GitHub Actions (ruff, mypy, pytest)

  2. Supply chain, maintenance, field service

    Operations automation agents

    Six agents that investigate a business event, decide, act through controlled tools and escalate to a person when required.

    Reference build: six agents, synthetic dataAutonomy: act with approval

    • 6agents on one shared pipeline
    • 7steps from event to verified action
    Read the full note
    The challenge
    An agent that can commit spend or change records needs hard limits and a full audit trail before it can be connected to core systems.
    The solution
    Agents for supplier disruption, maintenance triage, field-service rescheduling, procurement exceptions (three-way match), inventory stockouts, and a cross-domain operations control tower.
    Controls and evidence
    • One shared pipeline: gather → assess → validate → decide → approval gate → execute → verify.
    • Spend limits, approved vendors and tolerances are enforced in code. Writes are idempotent and verified by read-back. Every tool call is audited.
    • Run state is persisted, so a human approval can resume the work later.
    • The stockout agent survives a forced shutdown and replays safely.
    • Each agent ships with deterministic evaluations and unit tests. Without a model API key it falls back to a deterministic heuristic.
    Status
    All data is synthetic. The tool layer is designed to map onto a production ERP or enterprise asset-management system.
    Autonomy level
    Act with approval. Consequential actions wait for a person.
    Relevant to
    Global manufacturing, utilities, procurement and field-service operations.
    Technology
    Python 3.12, LangGraph, MCP, FastAPI, Pydantic, SQLite (simulated ERP/EAM), TypeScript, Vite

Simulation and decision support

  1. Emergency response, logistics

    Autonomous response-planning simulators

    Teams of autonomous drones learn to coordinate, and a live map interface lets stakeholders compare strategies before committing resources.

    Research paper, open code

    • 30scenes across 3 regimes
    • 0learned policies beat the simple rule
    Read the full note
    The challenge
    Emergency and logistics plans are costly to test in the field. A simulator lets decision-makers test them first.
    The solution
    Two connected platforms.
    • Wildfire response: Drones search bushland for fires and suppress them. Policies trained with DQN, MAPPO and MADDPG are compared against a hand-written greedy expert across 30 scenes in three regimes, including a stress regime with eight fires, lossy radio and a binding battery constraint. Documented in a research paper in conference format.
    • Flood relief: Drones deliver medicine and water to cut-off communities, scout roads and monitor slopes at risk of failure. Built on real terrain, road, population and river data from a recent major flood event. Runs on a standard CPU laptop.
    Controls and evidence
    • The flood model is calibrated against satellite-derived flood extents. Every calibration score and every failed acceptance gate is recorded.
    • Fixed seed pools separate training, checkpoint selection and held-out reporting.
    • Reported finding: A simple nearest-fire rule proved very difficult to beat, and no learned policy outperformed it. The paper lists its own limitations.
    Applicable to
    Logistics, emergency response, infrastructure monitoring and any problem of the form "compare strategies before committing capital". A deterministic simulation core, a streaming API and a map front end.
    Technology
    Python, NumPy, PyTorch, PettingZoo, FastAPI, WebSockets, React, MapLibre, Cesium, pytest

  2. Security and fraud

    Multi-model phishing detection

    Three independent models vote on whether a link is malicious, and the service continues if one drops out.

    Benchmarked ensemble

    • 97.1%LSTM accuracy on 62.5k held-out URLs
    • 99.6%LSTM ROC AUC on the same set
    • 92.0%ensemble accuracy, 1.71 s per URL
    Read the full note
    The challenge
    Any single model has a blind spot. Three different model types cover for one another.
    The solution
    XGBoost on 20+ URL features plus TF-IDF, a bidirectional LSTM on character sequences, and Llama 3.1 (via Groq) for semantic analysis with reasoning. An orchestrator fuses their confidence-weighted scores. If the language model is unavailable, the remaining models are re-weighted automatically.
    Results
    • The LSTM, trained on 250k URLs, reached 97.1% accuracy, 98.3% precision, 95.8% recall and 99.6% ROC AUC on a 62.5k held-out set.
    • The full ensemble reached 92.0% accuracy at 1.71 seconds per URL on a 600-sample benchmark.
    • Benchmark scripts for each model and for the ensemble are included, so the figures can be reproduced.
    Also delivered
    A web interface with confidence indicators and per-model breakdowns, a command-line tool and a Python API.
    Relevant to
    Security, fraud and trust-and-safety teams.
    Technology
    Python, XGBoost, PyTorch, Groq/Llama 3.1, scikit-learn, Streamlit

  2. Cheminformatics

    Drug-likeness modelling with validity review

    A labelled dataset and classifier built from 17,967 compounds in a public medicinal-plant database, with an independent review of what the score means.

    Research with independent validity review

    • 0.999headline AUC, partly circular
    • 0.945AUC from a single-feature rule
    Read the full note
    The solution
    A pipeline that cross-references 142 approved-drug seeds across 5 public databases. Clustering and PCA outlier removal yield about 14.4k drug-like and 3.2k non-drug-like compounds. Fingerprint-based structural splits, SMOTE/ADASYN for class imbalance, and an XGBoost classifier.
    The validity review
    The headline AUC of about 0.999 is partly circular, because the labels derive from the same features. A single-feature rule already reaches 0.945 AUC, so the next phase requires verified negative examples.
    Why it is included
    It shows the validity check we apply to any model before calling it complete.
    Relevant to
    Cheminformatics and ML teams that want an independent review of a result.
    Technology
    Python, RDKit, pandas, scikit-learn, imbalanced-learn, XGBoost, ChEMBL API

  3. Quantum computing

    Hybrid quantum-classical compression

    A hybrid compressor tested on real quantum hardware and under realistic noise.

    Executed on real hardware

    • 50image patches scored
    • 6noise levels tested
    Read the full note
    The challenge
    Claims about quantum advantage are easy to make and hard to verify. This work runs the circuits on real hardware and measures them against a classical baseline.
    The solution
    A Quantum Fourier Transform splits image patches from a standard benchmark into frequency bands. A variational quantum circuit, trained with PennyLane, learns which bands to keep.
    Method
    Evaluated on real quantum hardware (Qiskit Runtime) and under gate noise in a simulator, against a classical thresholding baseline. Scored with PSNR and SSIM over 50 patches at 6 noise levels.
    Delivered as
    Self-contained packages, single-file notebook versions, verification scripts and publication-ready figure generation.
    Relevant to
    Organisations assessing where quantum methods are, and are not, ready.
    Technology
    Qiskit, Qiskit-Aer, IBM Quantum Runtime, PennyLane, NumPy
